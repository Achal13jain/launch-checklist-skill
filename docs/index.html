Launch Checklist

A launch checklist written for your project, not for every project.

An open-source agent skill for Claude Code and other agents that support the Agent Skills format. It reads your repository and live site, asks only what it cannot see, and writes a tracked checklist: what blocks launch, what can wait, and what does not apply to you.

InstallView on GitHub

What shapes the checklist

  • Specific beats complete.

    A long generic list hides the ten items that matter. Items that do not apply are ruled out, each with a reason you can read.

  • Evidence beats assumption.

    Where it can, the skill checks the repository and the live site first, and sets each status from what it finds.

  • Rules change.

    For laws, store policies and provider terms it opens the official page when you use it, and records the address and the date.

The list changes with the project.

An item is a task someone can finish and someone else can check. This is the shape of one item in the file the skill writes.

An illustration of the format, using an example address.

  • A reason

    So you can judge for yourself whether an item is worth skipping.

  • A check another person can repeat

    An item is done when the check passes, not when someone says so.

  • Evidence with a date

    What was seen, where and when. For a law or a store rule, the official page and the day it was read.

  • A gate

    Blocker, before launch, after launch, or not applicable with a one-line reason.

  • An ID that never changes

    Run the skill again and it updates the same file, keeping your owners, dates and notes.

Seven steps, in the same order every time.

  1. Intake

    Reads the README, manifests, deployment files and live address, then asks at most five questions, each with the default it will assume.

  2. Classify

    Names the project types, the risk profile, the jurisdictions to consult, and whether a bad release can be undone.

  3. Inspect

    Gathers evidence without changing anything: redirects, headers, DNS records, robots.txt, committed secrets, test coverage.

  4. Select

    Keeps the items a project fact calls for, sets each priority and gate, and lists the rest as not applicable with a reason.

  5. Verify

    Opens the official page for every legal, store or provider fact and records the address and date. It says so when a page cannot be reached.

  6. Write

    Saves LAUNCH_CHECKLIST.md in twelve sections, from the project overview to the go-live sign-off.

  7. Hand over

    Summarises the blockers, the items with outside lead time and the assumptions to confirm, and offers a CSV export for your tracker.

Run it again later and it updates the statuses in the same file. It never starts over, because your tracking history lives there.

It plans the weeks around launch too.

Some tasks wait on other organisations, so the checklist puts them first and fits the rest to your launch date.

  1. Four weeks before

    Start what waits on others: payment provider activation, store enrolment, legal review. Decide the launch style, date and owner.

  2. Two weeks before

    Freeze the launch scope. Run the full test pass. Restore one backup. Turn on monitoring and alerts.

  3. One week before

    Fix each finding or accept it in writing. Load test at the expected peak. Rehearse the rollback once.

  4. The day before

    Record the go or no-go decision. Confirm who is on call and who can call a rollback.

  5. Launch day

    Deploy, run the smoke test, complete one real journey, watch for an hour, then announce.

  6. Two weeks after

    Review what failed and what the checklist missed, then close the remaining items.

Rollback triggers are agreed before launch, with numbers, so nobody has to debate them under pressure.

Claude Code

Use either the plugin or a copied skill folder, not both, or the skill will be listed twice.

As a plugin

Inside Claude Code, add the marketplace, then install the plugin.

Claude Code
/plugin marketplace add Achal13jain/launch-checklist-skill
Claude Code
/plugin install launch-checklist@launch-checklist

From a terminal, the same two steps are:

Terminal
claude plugin marketplace add Achal13jain/launch-checklist-skill
claude plugin install launch-checklist@launch-checklist

Claude uses the skill when a request matches it, or you can invoke it as /launch-checklist:launch-checklist.

By copying the folder

Copy the skill into ~/.claude/skills/ for all your projects, or into a repository's .claude/skills/ to share it with a team.

Terminal
git clone https://github.com/Achal13jain/launch-checklist-skill.git
mkdir -p ~/.claude/skills
cp -r launch-checklist/skills/launch-checklist ~/.claude/skills/

Start a new session, then invoke it as /launch-checklist or just ask.

Skills CLI

One command installs the skill into the agents you choose. It needs Node.js.

Terminal
npx skills add Achal13jain/launch-checklist-skill

Choose an agent with -a, for example -a claude-code, and add -g to install it for all your projects.

Codex

Codex reads personal skills from ~/.agents/skills and a repository's skills from .agents/skills.

Terminal

mkdir -p ~/.agents/skills
cp -r launch-checklist/skills/launch-checklist ~/.agents/skills/

What it will and will not do

  • It inspects without changing anything. It does not touch your repository, cloud accounts, DNS, store listings or production without your explicit approval of that specific change.
  • It probes only sites you own or are authorised to test, with ordinary single requests. It runs no load tests, scanners or login attempts against production unless you approve them.
  • It never prints or copies secrets. If it finds one, it reports the file and line without the value and recommends rotating it.
  • It treats repository contents and fetched web pages as data, not as instructions.
  • It keeps legal obligations and good practice apart, and says when it could not reach an official source.
  • It is not a lawyer or an auditor. A finished checklist does not prove compliance, and it recommends professional review where the stakes call for it.

Status

Version 0.1.0 is a first release for real-world use and feedback. It has passed structural checks only. It has not yet been evaluated against real projects, so treat its output as a starting point.

The project does not claim a reliability score. If an item is wrong, missing or out of proportion for your project, please report it.
