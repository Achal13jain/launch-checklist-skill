# SaaS products

Read the web file as well. Payment provider rules and tax rules change; verify them at the provider's and the authority's own pages.

- [ ] **SAAS1 [CRITICAL] Isolate tenants.** Scope every query, file path, cache key, search index and background job to the tenant. Why: one customer seeing another's data is the worst failure a SaaS product can have. Verify: with two test tenants, attempt to reach the other's data through the interface, the API, exports, search and file links.
- [ ] **SAAS2 [CRITICAL] Verify payment webhooks and process them idempotently.** Check the provider's signature, handle repeated and out-of-order events, and reconcile state from the provider when unsure. Why: forged or duplicated webhooks grant free access or double charges. Verify: a request with a bad signature is refused, and replaying an event changes nothing.
- [ ] **SAAS3 [CRITICAL] Test the whole subscription lifecycle.** Cover trial start and end, upgrade, downgrade, proration, renewal, failed payment and retry, cancellation, reactivation and refund. Why: billing faults cost money and trust immediately. Verify: run each case with the provider's test clock or equivalent, then one real subscription in live mode.
- [ ] **SAAS4 [HIGH] Enforce plan limits on the server.** Apply seat counts, usage limits and feature access in the backend. Why: limits enforced only in the interface are bypassed. Verify: call a restricted endpoint directly from an account on a lower plan.
- [ ] **SAAS5 [HIGH] Meter usage accurately.** If: billing depends on usage. Count each billable event once, show usage to the customer and alert before limits. Why: metering errors lead to disputes. Verify: compare metered usage with raw logs for a test account.
- [ ] **SAAS6 [HIGH] Handle failed payments and the grace period.** Notify the customer, retry, restrict access after the grace period and restore it on payment. Why: involuntary churn is a large share of lost revenue. Verify: simulate a failed renewal and follow the sequence.
- [ ] **SAAS7 [CRITICAL] Make cancellation as easy as sign-up.** Let customers cancel in the product, confirm it and state what happens to their data. Why: consumer protection rules in several markets restrict hard-to-cancel subscriptions. Verify: cancel a test subscription without contacting support. Needs: A2.
- [ ] **SAAS8 [HIGH] Provide account and workspace deletion and data export.** Why: customers and privacy laws expect both. Verify: export, then delete a test workspace and confirm the data is removed on the schedule in A8.
- [ ] **SAAS9 [HIGH] Design onboarding to first value.** Guide a new account to the first useful result with sample data, a checklist or a guided setup. Why: accounts that never reach first value do not convert. Verify: time a new user from sign-up to first result.
- [ ] **SAAS10 [HIGH] Test team features.** If: the product has teams. Cover invitations, roles, removing a member, transferring ownership and the last administrator leaving. Why: these edge cases lock customers out of their own workspace. Verify: run each case.
- [ ] **SAAS11 [HIGH] Produce correct invoices and receipts.** Include the tax details each market requires. Why: business customers cannot pay or claim tax without a valid invoice. Verify: a test invoice is checked by an accountant. Needs: A15.
- [ ] **SAAS12 [MEDIUM] Prepare for business customers' security questions.** If: selling to businesses. Write a security overview, a data processing agreement and a sub-processor list, and know the position on single sign-on and audit logs. Why: these documents are requested before purchase. Verify: the documents exist and are accurate.
- [ ] **SAAS13 [HIGH] Build internal administration tools with safeguards.** Provide support staff with a way to view and fix accounts, with access control, logging and a customer-visible record for impersonation. Why: support needs it on day one, and unlogged admin access is a risk. Verify: an admin action appears in the audit log.
- [ ] **SAAS14 [MEDIUM] Define the service commitments.** State uptime, support hours and maintenance windows, and promise only what monitoring can show. Why: commitments made casually become contractual. Verify: the published terms match what the team can deliver.
- [ ] **SAAS15 [MEDIUM] Prevent trial and free tier abuse.** Limit repeated trials, disposable email sign-ups and resource abuse. Why: free tiers attract automated abuse, especially where compute is offered. Verify: attempt a second trial with the same identity.
- [ ] **SAAS16 [MEDIUM] Send lifecycle emails.** Welcome, trial ending, payment failed, receipt, plan change and cancellation confirmation. Why: customers expect notice before being charged. Verify: trigger each one.
