# Browser extensions

Extension stores review every submission and every update, and they remove extensions that break policy. Read each store's current programme policies, listed in the sources reference, before submission and record the date.

- [ ] **EXT1 [CRITICAL] Request the minimum permissions and host access.** Prefer permissions granted on click and optional permissions over broad access to all sites. Why: broad permissions lengthen review, trigger warnings at install and are a frequent rejection reason. Verify: list each permission with the feature that needs it, and remove one at a time to confirm it is needed.
- [ ] **EXT2 [CRITICAL] Write a permission justification and a single clear purpose.** Why: stores ask for both in the submission form and reject extensions whose purpose is unclear or mixed. Verify: the listing describes one purpose and each permission has a written justification.
- [ ] **EXT3 [CRITICAL] Meet the store's current manifest and code requirements.** Use the manifest version the store accepts, bundle all code in the package, and avoid obfuscation and remotely loaded code where the store forbids them. Why: submissions that break these rules are refused. Verify: the package passes the store's upload validation, and a search of the code finds no remote script loading.
- [ ] **EXT4 [CRITICAL] Disclose data use and publish a privacy policy.** Complete each store's data use form to match what the extension collects and sends. Why: stores enforce their user data policies strictly, and browsing data is sensitive. Verify: capture the extension's network traffic and compare it with the declaration. Needs: A1, A3.
- [ ] **EXT5 [CRITICAL] Handle page content safely.** Treat everything read from web pages as untrusted, avoid inserting it as HTML, validate messages between content scripts and the background, and set a strict content security policy. Why: an extension flaw can expose every site the user visits. Verify: review each message handler and each place page content is used.
- [ ] **EXT6 [HIGH] Test in each target browser and after browser updates.** Why: extension APIs differ between browsers and change between versions. Verify: the main features pass in the current stable and beta versions of each supported browser.
- [ ] **EXT7 [HIGH] Test the update path.** Cover permission changes that disable the extension until the user approves, stored data migration and background worker restarts. Why: an update that adds permissions can silently disable the extension for everyone. Verify: install the previous version, then update to the new one.
- [ ] **EXT8 [HIGH] Prepare the store listing.** Name, short and long description, icons in each size, screenshots, promotional images, category and support contact. Why: incomplete or misleading listings are rejected. Verify: every required asset is uploaded and accurate.
- [ ] **EXT9 [HIGH] Give reviewers test instructions and credentials.** Why: reviewers reject what they cannot test. Verify: follow the instructions on a clean browser profile.
- [ ] **EXT10 [HIGH] Limit the effect on page performance and compatibility.** Why: an extension that slows or breaks popular sites is uninstalled and reported. Verify: measure page load on several popular sites with the extension on and off.
- [ ] **EXT11 [MEDIUM] Add onboarding after install and a feedback route on uninstall.** Why: users forget what an extension does unless shown immediately. Verify: install on a clean profile and follow the first-run experience.
- [ ] **EXT12 [MEDIUM] Secure the publisher account and plan for ownership.** Use two-factor login and a group publisher account. Why: hijacked extension accounts are used to push malicious updates. Verify: the account settings show two-factor login and more than one owner.
- [ ] **EXT13 [MEDIUM] Check storage limits and sync behaviour.** Why: extension storage has quotas, and synced settings can conflict across devices. Verify: fill storage to the limit and use the extension on two devices.
- [ ] **EXT14 [MEDIUM] Follow the store's rules for payments and for changing browser settings.** If: the extension sells features or changes the search engine, home page or new tab page. Why: stores set specific disclosure rules for both. Verify: compare the behaviour with the current policy text.
