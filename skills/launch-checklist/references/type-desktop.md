# Desktop applications

Installed software cannot be recalled. The update mechanism is the only way to fix a shipped build, so it deserves the most testing. Check the operating system vendors' current signing and distribution requirements at their own pages.

- [ ] **DESK1 [CRITICAL] Sign the application and installers for each platform.** Obtain the code signing certificates, sign every binary and installer, and complete any notarisation or reputation step the platform requires. Why: unsigned software is blocked or shown with warnings that stop most users. Verify: download the installer on a clean machine and install it without a security warning.
- [ ] **DESK2 [CRITICAL] Protect the signing keys.** Keep them in hardware or a managed key service, with access limited and logged. Why: a stolen signing key lets others ship malware under your name. Verify: the key cannot be exported by a developer account, and signing happens only in the release pipeline.
- [ ] **DESK3 [CRITICAL] Build and test the automatic update path.** Sign the updates, verify signatures before installing, and test updating from every version still in use. Why: a broken updater strands users on old versions permanently. Verify: update from the oldest supported version to the new one, and confirm that a tampered update is refused.
- [ ] **DESK4 [HIGH] Test install, upgrade and uninstall.** Cover a clean install, an upgrade that keeps user data, a downgrade, an uninstall that leaves nothing behind, and installs with and without administrator rights. Why: installer faults are the first thing users meet. Verify: run each case on clean machines for each supported operating system version.
- [ ] **DESK5 [HIGH] State and test the supported operating systems and hardware.** Cover processor architectures, minimum versions, display scaling and multiple monitors. Why: unsupported environments generate most support requests. Verify: the support matrix is published and tested.
- [ ] **DESK6 [HIGH] Collect crash reports with consent.** Send crash data with the version and symbol files, and let users opt out where required. Why: crashes on users' machines are otherwise invisible. Verify: a forced crash produces a readable report.
- [ ] **DESK7 [HIGH] Disclose telemetry and make it controllable.** Why: desktop users and privacy laws expect a choice about data leaving their machine. Verify: with telemetry off, no telemetry requests leave the application.
- [ ] **DESK8 [HIGH] Harden the application framework.** If: the application is built on web technology. Disable unneeded access from rendered content to the system, restrict navigation and loading of remote content, and keep the framework current. Why: a script injection in such an application can become full access to the machine. Verify: check the configuration against the framework's current security checklist.
- [ ] **DESK9 [HIGH] Store user data and credentials properly.** Use the platform's standard locations and its credential store, and handle data migration between versions. Why: wrong locations break backups and multi-user machines. Verify: inspect where files and tokens are written.
- [ ] **DESK10 [HIGH] Implement licensing and activation with an offline path.** If: the product is licensed. Why: a licensing fault locks out paying customers. Verify: activate, deactivate, move a licence to another machine and start the application offline.
- [ ] **DESK11 [MEDIUM] Meet store requirements.** If: distributing through an operating system store. Check sandboxing, entitlements and store policies. Why: store builds have different restrictions from direct downloads. Verify: the store build passes the store's validation.
- [ ] **DESK12 [MEDIUM] Host downloads reliably and publish checksums.** Why: users and security tools verify downloads. Verify: the download link is served over HTTPS from the product's domain and the checksum matches.
- [ ] **DESK13 [MEDIUM] Test behaviour with security software and corporate restrictions.** If: selling to businesses. Why: antivirus and managed machines block unknown software. Verify: install on a machine with common security software, and provide a silent install option for administrators.
- [ ] **DESK14 [MEDIUM] Check accessibility with the platform's assistive tools.** Why: desktop frameworks differ in how well they expose controls. Verify: operate the main journey by keyboard and screen reader.
